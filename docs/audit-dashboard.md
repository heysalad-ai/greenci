# Audit and repair dashboard

`/app/audit` extends GreenCI's existing product shell with an organisation-scoped repository audit, searchable/filterable inventory, per-repository findings, and a repair queue with real draft PR links. Repair state, local verification and hosted PR checks are separate. A draft with passing local tests can still have failed, blocked or absent GitHub checks. The page shows dated saved observations and does not claim continuous monitoring.

Only local/dev API environments expose `GET /v1/audit`. Existing session validation and membership checks apply, followed by an owner-role check. Artifacts are loaded from private R2 keys `audit/<session-org>/current.json`, validated with Zod, tenant checked and served with `private, no-store`. No browser upload or mutation route exists. Public preview assets contain no private report data. The dev App's practice-only write scope stays unchanged.

To refresh dev observations, use the existing authenticated CLI with `pnpm audit:dashboard <private-audit-report.json> <private-repairs.json> <private-output.json> [org]`. It queries each draft PR, rejects moved heads or non-draft/closed PRs, and records actual check rollups. Failed job billing annotations are distinguished when available. Upload only the validated organisation dataset to the existing dev R2 bucket. Keep all inputs/outputs in ignored private storage.

`pnpm repair:publish <private-plan.json>` publishes a review branch from an exact, freshly checked parent commit. It validates source hashes before creating a commit, restricts changes to dependency manifests/locks plus explicit operator-approved, non-sensitive source/test paths, and refuses default-branch pushes through the core guard. `mode: update` accepts only a fast-forward update to the same repair branch. It never creates/approves/merges a PR, changes repo settings, installs an App or executes customer code. Draft PR creation remains an explicit authorised operator action through the GitHub connector. Current repairs are operator-assisted local GreenCI runs; the hosted UI is an evidence/review dashboard, not a general multi-repository repair executor.

Tests use fake data and local Workers bindings: schema/PR URL validation, unsafe publish paths, anonymous/reader/other-tenant denial, private cache headers, search/filter/detail keyboard focus, mobile overflow and auth/error recovery. Real GitHub calls happen only during the explicit operator run. No audit result or private repository data belongs in a commit.
